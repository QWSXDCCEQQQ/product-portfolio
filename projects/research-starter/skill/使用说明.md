# 技能包使用说明

技能名称 `research-starter-workflow`　版本 `0.1.2`　日期 2026-11

## 导入

把 `02_技能包/` 目录下的全部文件按原结构打包成 zip，上传到 WorkBuddy 的技能导入窗口。包结构：

```text
SKILL.md
references/task-contract.md
references/paper-selector.md
references/paper-reader.md
references/paper-presenter.md
使用说明.md
```

`SKILL.md` 必须位于压缩包根目录，不能被再套一层文件夹，否则导入会失败。

包内已有一个旧名版本 `research-starter`，两者可共存。本版使用独立入口名 `research-starter-workflow`，避免同名混淆。

## 调用前先做一次身份核对

新对话里明确输入完整技能名，让宿主先证明确实读到了文件：

```text
请使用 research-starter-workflow（科研启航论文组会工作流）。
请先实际读取该 Skill 的 SKILL.md，告诉我：
1. 入口文件的实际路径；
2. name 和 metadata.version；
3. 三个包内工作模块的相对路径。
若未找到此技能，请说明未找到，不要用 research-starter 替代。
```

预期返回：`name` 为 `research-starter-workflow`、`version` 为 `0.1.2`，模块为三个 `references/*.md` 路径。

**验证要点**：看过程记录里是否真的有文件读取动作，不能只凭回答文字判断已加载。同名技能共存的场合，这一步能区分到底加载了哪个版本。

## 首次交互的环境检查

入口会先确认三件事：能否联网、能否读取论文 PDF、能否生成 PPTX。

任何一项缺失，当轮就会说明影响并给出当前可交付的内容，不让用户等到最后一刻才发现只有文字。这是有意设计的降级，不是故障。

## 建议的第一次使用

不要一上来就让它走完整条流水线。按你实际的卡点进：

| 你的状态 | 从哪进 |
|---|---|
| 还没有论文 | 说清汇报对象、时长和方向，让它做候选比较 |
| 已有论文，读不懂 | 直接贴论文或章节，从具体段落切入 |
| 读懂了，要出大纲 | 给它你的理解记录，直接进汇报制备 |

只问一个问题时，它不会生成整条流水线——这是设计约束，不是能力不足。
