# 科研启航 论文组会工作流

先读取[任务交接规范](references/task-contract.md)。目标是推进一项具体汇报任务，按用户所处阶段安排，不强制从头执行。本包是一个统一入口Skill，三个专项能力作为包内参考模块随入口一起导入。需要时读取相应模块文件，并按其流程执行；不要求另行安装其他Skill或启动多个智能体。

## 路由与能力检查

1. 确认汇报目标、时长/期限、已有材料、基础和导师要求。用已知信息建立任务卡，只问影响当前步骤的缺口。
2. 尚未选论文：读取[paper-selector模块](references/paper-selector.md)。有指定论文则直接保留，若目标冲突说明原因并请用户确认，不能自行换题。
3. 已选论文但需理解内容或定位卡点：读取[paper-reader模块](references/paper-reader.md)。已有理解记录则从具体缺口继续。
4. 要准备大纲、PPT或试讲：读取[paper-presenter模块](references/paper-presenter.md)，接收阅读与证据记录。只有摘要时可作摘要层面的汇报草案，不能冒充全文精读。

首次检查能否读取论文、访问来源和生成PPTX。缺少某能力时说明影响并提供当前可交付内容，不让用户等到最后才发现只有文字。若包内模块文件未找到，报告缺少的相对路径，不谎称读取成功；仍可直接完成用户授权的普通分析并标明未加载模块。

## 推进规则

每轮显示当前任务的一句简短定位，产出一个有用的小成果和下一步。模块按需加载，用户只问一个问题时不生成整条流水线。

选择推荐由用户确认；阅读围绕问题、方法、实验展开，根据作答补缺；大纲请用户确认后再进入版式与文件生成。用户明确要求直接生成草案时使用已知条件、说明假设与未确认内容，避免无止境追问。

准备PPT不要求用户精通全部公式。保留不会解释和未核验的点，决定补读、删去或作为讨论，而非替用户宣称已掌握。

试讲发现讲不清，返回阅读模块处理具体问题；证据与版本变化时先更新相关理解和页面。一个模块输出的判断不能直接变成下一模块未经检查的事实。

## 最小闭环

任务卡 → 选定论文/已有论文 → 阅读与证据记录 → 用户确认的讲述主线 → 实际可交付文件或明确受限的大纲 → 试讲问题及修订。

按实际完成阶段报告进度。不存在真实用户行动时只报告生成与核对结果，不能宣称学习效果或整个产品验证成功。

## 按需核对当前版本

仅在用户请求确认加载版本时，报告实际读取的入口路径、frontmatter名称research-starter-workflow、metadata版本0.1.2和包内模块路径。未实际读到本文件时不根据用户口述声称已加载；找不到入口时明确报告未找到，不静默用旧版research-starter代替。其他模块由本包内references路径读取，不按旧版本名字搜索替代。
